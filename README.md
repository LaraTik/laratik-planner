# laratik-planner

> Social media planning, design, and approvals for one agency.
> Self-hosted Next.js + Drizzle + Postgres + NextAuth on the LaraTik VPS.

This repo is the LaraTik port of the **[StudioFlow Production Development Master Prompt](./STUDIOFLOW_MASTER_PROMPT.md)** — a 3,000-line product + engineering spec generated by another Codex session. The spec was written for Supabase + Vercel; we kept the product spec verbatim and ported the data layer, deploy, and email to our self-hosted stack. Every deviation is recorded in [`PORT_NOTES.md`](./PORT_NOTES.md).

## Live status

- **Goal 0** ✅ — production foundation (this commit)
- **Goals 1–14** ⏳ — see [`docs/implementation/progress.md`](./docs/implementation/progress.md)

The app is being built goal-by-goal. Each goal is one self-contained PR with verification evidence.

## Stack at a glance

| Layer     | Choice                                             |
| --------- | -------------------------------------------------- |
| Framework | Next.js 16 (App Router) + TypeScript strict        |
| UI        | Tailwind 4 + shadcn/ui + Radix                     |
| DB        | Postgres 16 (sidecar) + Drizzle ORM                |
| Auth      | NextAuth v5 (Auth.js) + Drizzle adapter            |
| Providers | Google OAuth + email magic link                    |
| Email     | Nodemailer → Mailcow SMTP (`mail.laratik.com`)     |
| AI        | MiniMax (`MiniMax-M3`) — optional, Goal 11         |
| Tests     | Vitest (unit) + Playwright (E2E + a11y)            |
| CI        | GitHub Actions → GHCR                              |
| Deploy    | `docker compose pull` on `laratik-vps` via Traefik |

## Quick start

```bash
# 1. Clone
git clone https://github.com/LaraTik/laratik-planner.git
cd laratik-planner

# 2. Install
pnpm install

# 3. Copy env
cp .env.example .env
# Edit .env: at minimum set AUTH_SECRET (openssl rand -base64 32)

# 4. Start Postgres + Next.js
./scripts/dev.sh

# → http://localhost:3000
# → http://localhost:3000/api/health  (returns JSON: { ok, version, env, db, uptime, timestamp })
```

## Daily ops

```bash
./scripts/project.sh status              # container states + health
./scripts/project.sh logs [app|postgres] # tail logs
./scripts/project.sh restart [app]       # bounce container
./scripts/project.sh shell [app|postgres]
./scripts/project.sh health              # app + db reachability
./scripts/project.sh migrate             # pnpm db:migrate
./scripts/project.sh backup              # pg_dump → ./tmp/backups
./scripts/project.sh rollback <sha>      # roll to previous image
./scripts/project.sh env                 # show .env with secrets masked
```

## Deploy

```bash
# From local — push to VPS
./scripts/deploy.sh                      # pulls :latest
./scripts/deploy.sh <sha-or-tag>         # pulls specific commit
```

CI is set up to build and push the image to GHCR on every `main` push. The deploy workflow SSHes to `laratik-vps` and runs `scripts/deploy.sh <sha>` automatically.
